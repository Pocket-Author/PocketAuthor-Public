# PocketAuthor Use Cases

## Founder → business book

**Inputs:** company history, founder notes, product decisions, investor updates, talks, internal memos, customer lessons.

**Workflow:** define thesis → build outline → extract recurring lessons → interview founder/team → draft chapters → verify claims → edit → publish.

**Output:** a durable book that communicates the founder's ideas beyond a pitch deck or social feed.

## Researcher → public-facing book

**Inputs:** papers, notes, literature, datasets, interviews, field observations.

**Workflow:** identify the public argument → separate primary and secondary evidence → build chapter structure → translate technical work into accessible prose → preserve citations and provenance.

**Output:** an evidence-based book for a broader audience.

## Creator → long-form book

**Inputs:** newsletters, videos, podcasts, posts, audience questions, essays.

**Workflow:** cluster themes → identify the strongest thesis → remove repetition → add missing research → convert fragments into coherent chapters.

**Output:** a book that turns ephemeral content into a durable intellectual asset.

## Coach or consultant → framework book

**Inputs:** frameworks, workshop material, client patterns, exercises, templates, case studies.

**Workflow:** define method → structure progression → add stories and examples → build exercises → review confidentiality → publish.

**Output:** a practical guide that explains the author's method at depth.

## Nonprofit or community organization → field knowledge book

**Inputs:** reports, interviews, oral history, program notes, community knowledge, photographs, research.

**Workflow:** establish editorial principles → collect and permission stories → organize evidence → write collaboratively → review representation and rights.

**Output:** institutional memory, public education, or a community-authored book.

## Technical expert → practical handbook

**Inputs:** documentation, implementation experience, technical notes, standards, case studies.

**Workflow:** define reader skill level → build task-oriented chapters → verify current technical claims → create examples → edit for clarity.

**Output:** a useful reference book rather than disconnected documentation.
